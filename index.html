01 / 平时怎么开玩

一个窗口管理多台远程 Steam。

这是 Moonlight 路线的日常入口。首次配置交给两端 agent；游戏仍由你在 Steam 库里自己选择。

远程 Steam 管理器

选择服务器 → 查看 Steam / 串流和 GPU 状态 → 连接或启动 → 同一窗口切卡、关闭会话。

不开新游戏、不自动读档。保留已建立的 VPN；便携客户端使用固定工作目录，默认关闭串流统计并使用相对鼠标。

全屏 / 窗口：先点击 Moonlight，按 Ctrl + Alt + Shift + X，再按一次切回。想以后默认全屏，在下方参数选择“全屏”并更新本机私有启动配置。
  1. 开机后，等待你原有的 VPN 和网络就绪。
  2. 打开桌面“远程 Steam 管理器”，选择服务器。

    点击“连接 / 启动 Steam”：已运行就直接连接，不强迫重新选卡；未运行才按所选渲染 / 编码 GPU 启动。切卡使用“应用所选 GPU 并连接”。

  3. 连接后在远端 Steam 库里选择游戏。

    账号登录过期时由你完成登录。首次授权、系统安全提示和游戏隐私选择不会被脚本代办。

一份服务器配置

private/servers.json 保存服务器名称、SSH 主机 / 账号 / 端口和 Moonlight 地址；可以新增、禁用服务器，窗口内重新加载配置。真实值只保存在本机。

四卡状态与独立选卡

显示显存、GPU / 编码利用率、温度、功耗和 python* 进程别名。渲染与串流编码分别选卡；点击显卡行核对原始名称与 PID。

关闭也在同一窗口：先选择服务器，点击“关闭所选服务器的会话”。脚本先重新检测，已经关闭不重复操作；游戏仍运行时要求先保存退出。不会关闭服务器或停止其他计算任务。
第一次如何生成这个桌面入口？

让本地 agent 阅读 client.md 的“一键启动远程 Steam”章节，将多服务器示例填好并保存为本机 private/servers.json，再为 scripts/open_remote_steam.py 创建指向 pythonw.exe 的一个桌面快捷方式。连接、选卡与关闭共用同一管理窗口；旧单服务器 launcher.json 仍兼容。server agent 须先部署对应的 start-session.sh。仓库不是跨所有机器的一键服务器安装器。

交给本地 agent →交给远端 agent →
如果你要的是“主程序留本地、只借远端 GPU”，请使用第 03 节 Juice 路线，而不是把 Moonlight 叫作本地图形转发。

05 / 远端运行保障
先确认远端开着，再确认服务就绪。
桌面入口能启动已部署的软件。远端机器本身必须开机、联网、SSH 可达；本地断线、服务器重启和应用崩溃是不同情况。
当前默认：连接时补启动
管理器先只读检测：已有 Steam / Sunshine 就直接连接；缺串流时按原配置恢复；Steam 未启动时按所选 GPU 调用幂等 start-session.sh。关闭 SSH 不会等于关闭这些已脱离会话的后台进程。
可选：长期巡检与开机恢复
由 server agent 安装用户级 systemd 服务，检查、补启动，并按需开启 linger。此配置尚未默认替你启用；安装方法见 server.md 的 C 节。
① 远端只读检查
先让 server agent 把仓库 scripts/server-health.py 部署到下面的示例位置，再在 SSH 中执行。默认不修改运行状态。
远端 LINUX · Moonlight 路线
返回码 0 且 JSON 的 ready=true 表示显示、音频、Sunshine 端口、本人 Steam 和会话入口通过基础检查。它不保证账号已登录，也不能代替实际画面与 NVENC 验收。

--ensure 只在检查失败时调用 start-session.sh 并复查，不自动启动游戏、不重置配对、不杀已有进程。卡死、端口冲突或 GPU 被占用时仍需定位原因。
Juice GPU-over-IP 路线检查
远端 LINUX · agent 目录须与实际解压布局相符
核对属于自己的 agent、回环端口和 nofile；renderer 的目标 GPU 和继承限制仍须在实际应用运行时确认。
开机自启、异常恢复和停用方法
仓库提供两个用户级 systemd 示例：gpuip-juice-agent.service 用于前台 Juice agent；gpuip-session-watch.service 每 60 秒检查串流服务，按需补启动远端 Steam。先按实际路径部署，再 enable。
想在服务器重启、用户未登录时启动，还要检查 loginctl 的 Linger=yes；启用 linger 可能需要管理员权限。只开 nohup 或只启动一次服务不等于开机恢复。无需重启共享服务器来试验。
停用下次自动启动可执行 systemctl --user disable 对应服务；立即 stop 前先保存退出游戏。服务创建的子进程也可能随 stop 退出。查看完整安装、检查与停用命令 →

07 / 退出和快速排错
先正常退出，再按自己会话的边界清理。
保留远端游戏
Moonlight 按 Ctrl+Alt+Shift+Q，只断开画面。下次桌面一键入口重新连接同一会话。
释放游戏显存
在游戏内正常保存并退出，再断开串流。Juice 先关闭本地应用，再关闭自己的隧道；不结束不明 renderer 或其他用户作业。
Moonlight 提示未配对 / Error 503
先核对便携工作目录；已有证书不要重置。503 可能是旧串流连接还未释放：断开旧客户端，等它被清理后再连，不重启整台服务器。
SSH 不通，但 VPN 必须保持
先分辨地址、端口、认证和路由。桌面启动器的物理网卡回退是显式可选项，仅在一块启用物理网卡且目的主机匹配时生效；不修改全局路由，也不代表 Moonlight UDP 同时改道。不要把关闭 VPN 当成默认方案。
Downloads disabled、黑屏或程序退出
查实际选择的 Proton 和对应 Steam Runtime 是否安装；区分游戏退出、Steam 先退出、正常加载与串流断线。MFC 缺失、文件描述符耗尽、Steam IPC 断开是不同故障，不把它们都归因到 GPU 性能。保留私有日志，公开报告先脱敏。
画面很卡，应该看哪组数据？
先看 Moonlight 网络丢帧与解码，再看游戏 FPS 和帧时间。首次 shader 编译、菜单、加载和实际关卡分别标记；编码 60 FPS 可能包含重复游戏帧。不要依据某个菜单片段宣称实玩性能翻倍。
键鼠快捷键速查
Ctrl+Alt+Shift+X：全屏/窗口；Z：捕获/释放键鼠；S：串流统计；M：鼠标模式；Q：断开串流。组合前先让 Moonlight 获得焦点。
